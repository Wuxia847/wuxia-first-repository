# 设计总览

给一个"bot"加一层**潜意识**：它不负责说话，只负责**记得住、感觉得到、有自己的时间**。
说话仍然交给大模型。

大脑=大模型，负责输出与输入内容（可换）

潜意识/人格=小模型，作为潜意识实时处理简单却重要信息（或许可以省token?)

目前是本地+云端，本地生成提示词，云端输出

astrbot+snowluma+vnc+云端服务器+qq

---

## 一、四层数据流

```
① 事件层   原始对话，只追加，永不改写
              ↓ 只读
② 派生层   引文卡（一句原话）→ 话题（一件没完的事）
              ↓ 固定预算
③ 状态层   四维向量（亲密/信任/张力/热度）+ 散文渲染//电脑撑得住可以继续增加向量，可能更准确？
              ↓
④ 人格层   人格锚（只读的自我描述）+ 体检/谱系
```

**大模型只吃③④的产物，永远看不到①②的原文。**
这是为了防止"上下文黑洞"：历史越长，越不能整包塞进提示词。

---

## 二、四本账（缺一本就会烂）

| 账 | 可改性 | 作用 |
|---|---|---|
| **事件账** | 只追加，永不改 | 唯一的真相来源 |
| **记忆账**（卡片/话题） | 可派生、可作废 | 可回指的碎片与线索 |
| **状态账** | 可重算（保留快照） | 关系的坐标 |
| **人格锚账** | **只读**（新增与退休，不改写） | 防漂移的底线 |

**铁律**：程序只能"提议"改人格锚；漂移超阈值 → **报警，不自动修正**。

---

## 三、三条不可让的底线

1. **只改不造**
   记忆存原话，不写摘要；摘要会引入错误，而且越总结越像"别人对ta的描述"。
2. **空是合法的**
   检索不到就一条都不给；没想说的话就留空。宁可少说，不要硬凑。
3. **不打扰**
   所有主动行为都要过闸门；"想发但没发"必须留痕，否则无法判断ta是变安静了还是变吵了。

---

## 四、状态用两个时间尺度

| 变量 | 尺度 | 直觉 |
|---|---|---|
| 亲密、信任 | 按**共同天数**缓慢增长 | 关系是熬出来的，聊得多不等于亲密 |
| 张力、热度 | 按**小时**衰减（半衰期 72h） | 热度是聊出来的，停三天就凉 |

为什么不用"消息条数"：那会让频繁斗嘴变成"关系很好"。
停聊三天，热度掉 90%，亲密只掉 0.002——**这才是人的感觉**。

---

## 五、给模型看的是散文，不是数字

内部坐标是给程序用的：

```
intimacy 0.60 / trust 0.55 / tension 0.10 / warmth 0.42 / 8h 未说话
```

注入给模型的是**词**：

```
你们挺亲近，还算信ta，没什么疙瘩；气氛正热。ta已经 8 小时没说话了。
```

依据是一条第一性原则：**字符是语言模型的母语，感知 ≠ 计数**。
数字适合做坐标系（选记忆、算衰减），词才适合做"感觉"。

---

## 六、不新增引擎，新增事件源

做"主动性"最容易犯的错是造一个"主动引擎"。正确的做法是：
让已有的心跳循环**多产出几种事件**（欲望、观察、梦、仪式），
主动行为只是这些事件经过闸门后的出口。

**tick 不落账**：心跳只更新元数据，不写进事件账——否则账本会被心跳淹没。

---

## 七、预算（这是防黑洞的关键）

| 产物 | 上限 | 频率 |
|---|---|---|
| 状态包（散文） | 200 字 | 每轮 |
| 人格锚 | 150 字（≤6 条） | 每轮 |
| 话题上下文 | 120 字（≤1 个） | 命中时 |
| 沉淀视图（"醒来"看到的） | 600 字 | 一天一次 |
| **合计** | **≤1070 字** | |

同步路径**不跑模型**（只读缓存）；异步代谢挂在已有的心跳上，不新增节律。

---

## 八、可回滚

网关有三档：`passthrough`（只记录）/ `enrich`（追加状态）/ `replace`（接管系统提示）。
改一个环境变量就能退回原样——**任何接管都必须能一分钟内撤回**。
