# 记忆与人格

这一篇回答四个问题：(作者认为）记忆是什么、人格是什么、怎么写、怎么改。

---

## 一、记忆的四层

| 层 | 是什么 | 能否进化 | 能否当引文 |
|---|---|---|---|
| L0 事件 | 一条原话 + 谁说的 + 时间 | 只追加 | ✅ 唯一事实 |
| L1 引文卡 | 从一段对话里挑出的**一句原话** | 可改/钉住/作废 | ✅ |
| L2 话题 | 若干张卡指向**同一件没结束的事** | 有生命周期 | ❌ |
| L3 人格锚 | 关于**ta自己**的稳定描述 | 只增与退休 | ❌ |

**判定标准一句话：能不能回指到原文。**
回指不到，就不是记忆，只是推测——不许写成引文。

---

## 二、卡片：为什么是引文不是摘要

> 摘要会引入错误，而且越总结越像"别人对ta的描述"。

一段对话产 **1–2 张卡**：ta_A说的一句 + ta_b说的一句。（结构完善后可以增加更多关系卡）
只记一侧，记忆就只有一半——后面提炼人格时，会全部变成"ta_A的话"。

**这一步踩过的坑**：最初的实现只从"用户消息"里挑引文，
结果一百张卡全是ta_A说的，从里面提炼出来的"ta_B的性格"必然全是复述。

---

## 三、话题：不是标签，是"还没结束的事"

```
open（进行中）──14 天没动──▶ dormant ──复活──▶ open
                                 └──确认──▶ closed
                 合并 ──▶ merged
```

**四个用途**，只用前两个的话，话题就等于白做：

1. 检索命中后展开上下文（补前因后果）
2. **主动开口的由头**——只有"还开着的事"才值得问
3. 醒来回顾（"还有 2 件事没完"）
4. ta_B所在意的线索 → 人格锚的素材

### 铁律：话题不参与检索打分

它在**命中之后**才展开。否则同一件事的十张卡会互相抬分，把别的话题挤掉。

### 状态写法的四代教训

| 版本 | 例子 | 问题 |
|---|---|---|
| v1 摘要 | "用户正在改配置，助手提醒别弄坏" | 第三人称旁白，不是ta_B |
| v2 口吻 | "这就收拾，马上走" | 有口吻了，但**角色颠倒**（在办公室的是ta_A） |
| v3 视角 | "ta_A提醒办公室已没人；我催收拾回去" | 分工对了，但**动词挂错人** |
| **v4 动作归属** | **"ta_A还坐在空办公室；我催他收拾回去"** | ✅ |

**结论**：催 / 劝 / 提醒 / 让 这类"推动对方去做"的动作**永远是ta_B的**，
只能写在"我"那栏；ta_A那栏只写处境。这条必须写进提示词，还要机械校验。

## 四、人格锚：三类 + 阈值

| 类型 | 写什么 | 证据必须来自 | 跨度 |
|---|---|---|---|
| 性格 `self` | ta怎么说话、什么脾气 | **只有ta自己说的话** | ≥3 天 |
| 行为 `behavior` | ta对他固定的反应 | 双方，描述ta的行为 | ≥3 天 |
| 关系 `relation` | 两者的默契 | 双方 | ≥7 天 |

**校验四条（不信任模型）**：

1. 依据必须能在**对应那一侧**的原文里找到 → 找不到，丢弃
2. 支撑证据 ≥3 条不同事件
3. 时间跨度达到上表
4. 同一话题下相反行为 >30% → 丢弃

> 归因校验是确定性的：模型标什么来源不算数，**以原文出处为准**。

---

## 五、怎么改：只增与退休

| 操作 | 允许 |
|---|---|
| 自动改写已确认的锚 | ❌ 程序的权限到"提议"为止 |
| 新增一条 | ✅ 走完整校验 |
| 解除（retired） | ✅ 用户来点 |
| 改措辞 | ➡️ 视为"解除旧的 + 新增新的"，记 `replaced_by` |

谱系是"人格在长"的唯一可验证证据：

```
锚 #12「我嘴硬」            retired, replaced_by=#31
锚 #31「我嘴硬，但会先服软」  active
```

---

## 六、人格会变，所以要有体检

每月跑一次（**只出方案，不改任何东西**）：

```
支持 ≥3 条        → 保留
支持 1–2 条       → fading（褪色中）
支持 0 条         → 建议复查
反证 ≥3 条/跨 7 天 → 建议修订
```

没有**反证搜索**，人格只会在一条路上越走越窄——只会找"支持我的证据"，
迟早变成一个人的夸张漫画。
