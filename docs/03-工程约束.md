# 工程约束与踩坑清单

这一篇是"用血换来的"：每条都对应一次真实的故障。借鉴一下能省很多时间（当然 也可能限制你自己）

╥﹏╥

---

## 一、零依赖

整套只用 Python 标准库 + SQLite。理由：

- 装得越少，跑得越久。这类系统是**常驻**的，依赖会烂。

- 向量检索在这个规模（几千张卡）用暴力算就够，不需要向量库。

  （先跑起来再上向量库）

- 中文分词不需要分词器：**双字重叠**（bigram）比 FTS5 的 trigram 好，
  因为 trigram 搜不到两个字的词。

---

## 二、只追加的事件账

- `INSERT OR IGNORE` + `UNIQUE(hash)`：重复导入不会产生重复事件。
- 想"删数据"时先想清楚：**删事件等于篡改历史**。
  要去掉一条记忆，应该"作废卡片"，而不是删事件。
- 派生数据（卡片/话题）可以重建；事件不行。

---

## 三、网关（把自己插在客户端和模型之间）

（在先进行云端部署再打算至切换本地+云端的情况下）

### 三档必须都留着

```
passthrough  只记录（最安全，先跑这个）
enrich       追加状态包（保留对方人格）
replace      接管系统提示（人格完全自持）
```

**先跑 passthrough 至少一天**，确认链路稳定再升级。

### 四个必做

| 问题 | 现象 | 解法 |
|---|---|---|
| 历史整包发 | 一次请求十几 MB，首字延迟 7 秒 | 裁剪到最近 N 条（保留第一条 system） |
| 图片 base64 | 占了 99% 的体积 | 换成 `[图片]` 占位符再转发 |
| 流式分块缺字段 | 客户端校验失败、重试、更慢 | 合成的 chunk 必须带 `id/object/created/model`，并以 `finish_reason: stop` 收尾 |
| 插件噪声 | 定时任务指令被当成"她说的话" | 按结构判定来源，见下 |

### 不持有密钥

原样转发调用方的 `Authorization`。网关不该成为第二个密钥泄漏点。

## 四、谁在说话：结构判定，不猜语气

```
assistant            → self
tool / system        → 永不进记忆
带注入标记的（[cronjob]/[schedule]/<system_reminder>） → system
其余 user            → human / other
```

**两条反直觉的教训**：

1. **注入标记必须优先于角色**。定时任务的指令经常以 `assistant` 角色入库，
   只看 role 会把它当成"ta自己说的话"。
2. **不能要求"必须有 MSG_ID 才算真人"**。我们自己的网关在入库前就把标记清掉了，
   用这个当判据会把真人的话误判成系统提示。

## 五、常驻进程：单实例锁

Windows 上 `SO_REUSEADDR` 允许多个进程绑同一端口——
"启动失败就退出"防不住重复实例，会悄悄跑出 5 个守护进程。

**做法**：另开一个锁端口，占不到就退出。守护/Web/隧道各一个。

---

## 六、隧道与端口

- 容器里的进程看不到宿主机的 `127.0.0.1`，要走**网桥网关 IP**（如 `172.18.0.1`）。
- 反向隧道断开后，端口可能被**僵尸 sshd** 占着，表现为"绑定失败"。
  要清理残留会话，而不是反复重试。
- **批处理文件里不要写中文注释**：Windows 控制台按 GBK 解码，会把注释解析成命令。

---

## 七、兜底：不要在应用层做，要在网络层做

实测：应用自带的 provider fallback 可能只试一个就放弃，而且重试链路要 30 秒。

更可靠的做法是在服务器上放一个极小的路由器：

```
客户端 ──▶ 路由器 ──▶ 本地（可用时）
                    └─▶ 上游直连（不可用时）
```

**两个必踩的坑**：

1. **健康探测不能只看端口**：反向隧道的端口在后端死掉时仍然是 LISTEN 的，
   必须真的发一个 HTTP 请求。
2. **转发失败要立刻重试另一条路**，不要等下一次请求。

---

## 八、可观测性

每轮请求写一行日志，包含：`模式 / 条数 / 字符数 / 连接耗时 / 首字耗时 / 总耗时 / 是否真人对话`。

出问题时能一眼看出是"上下文太大"、"上游慢"还是"链路断"。

---

## 九、测试优先级

按"错了会很贵"排序：

1. **引文保真**：卡片引文必须能在事件里逐字找到
2. **归因**：每条锚/话题的依据必须能回指到原文
3. **预算**：注入内容的长度上限
4. **闸门**：安静时段、每日上限、退避
5. **幂等**：重复导入/重复重建不产生重复数据

前两条出错，整个系统就变成"编造的记忆 + 编造的人格"，很难察觉。
